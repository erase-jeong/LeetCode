p1.id>p2.id가 가장 작은 것만 남기는 조건이 되는 이유??
=> 삭제할 대상을 찾는 조건이기 때문이다.

가장 작은 것을 남기려면-> 가장 작은 것이 아닌 것을 삭제하면 된다.

논리흐름을 보자.

목표가 중복 이메일 중에서 id가 가장 작은 행만 남기고 싶다. 
뒤집어 생각하면, 더 작은 id를 가진 동일 이메일 행이 존재하는 행을 삭제하면 된다.

sql로 표현하면 
p1.email=p2.email (같은 이메일인데)
AND p1.id>p2.id (p1보다 id가 작은 p2가 존재한다 = p1은 살아남을 자격이 없다)

예를들어서
id=1,3,4 모두 다 email이 a@test.com 이라고 하면
id=3은 같은 이메일에 id=1(더 작은 것)이 존재한다 => 삭제 대상
id=4입장에서는 같은 이메일에 id=1,3(더 작은 것)이 존재한다 => 삭제 대상
id=1입장 => 같은 이메일에 자신보다 자신보다 작은 id가 없다 => 살아남는다.


p1.id>p2.id => 나(p1)보다 작은 id의 쌍둥이(p2)가 존재하면 나는 삭제!!
=> 결국 가장 작은 id만 이 조건에 걸리지 않아서 살아남는다.

즉, 남길 것을 직접 지정하는 것이 아니라 '삭제할 것'의 조건을 반대로 표현하는 것이다. 
=> 이렇게 할 수 밖에 없는 이유는, SQL의 DELETE 특성 때문이다.

SQL의 DELETE는 '이 행을 지워라' 라고만 말할 수 있고 '이 행을 남겨라' 라고 직접 말하는 문법이 없다. 

비유를 하자면
'반에서 1등만 남기고 싶다' 라는 것은
- 1등을 남겨라 -> 선생님이 실행할 수 없음
- 1등이 아닌 애들을 한 명씩 내보내라 -> 실행 가능
